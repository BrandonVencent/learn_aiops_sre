## Q&A

### 1. 部署时遇到过什么问题？怎么发现的？怎么解决？

按"现象 → 发现 → 定位 → 修复"讲四个。

#### Grafana OOMKilled

- 现象：Pod 反复重启。
- 发现：`kubectl describe pod`，`Last State: OOMKilled`。
- 定位：Grafana 13.2.4 启动加载 56 个插件，limit 只有 256Mi。
- 修复：提到 512Mi，RESTARTS 归零，事件不再出现 OOM。如果 512Mi 还 OOM，下一步 768Mi，一次只改一个参数。
- 经验：换版本（Grafana 13）内存预估要重做。

#### Tempo 首次安装失败

- 现象：`helm upgrade --install` 报 connection reset。
- 发现：报错发生在下载 `tempo-3.2.1.tgz` 阶段，Kubernetes 资源还没创建，排除集群问题。
- 修复：Windows 下载同一官方 chart，SHA256 校验，解压核对 `Chart.yaml` 的 `version` / `appVersion`，`scp` 到 server 本地安装成功。
- 经验：网络受限环境要有"离线产物 + 校验"的习惯，不能只重试。

#### OTel Collector exporter 别名

- 发现：collector 日志 `otlp alias is deprecated`。
- 定位：0.163.2 中 gRPC exporter 的名字是 `otlp_grpc`，`otlp` 是兼容别名；receiver 仍叫 `otlp`。
- 修复：改 exporter 名，滚动重启，warning 消失。
- 经验：锁版本要读 changelog；改名类变更要隔离到受影响的字段。

#### ai-summary startupProbe 被杀

- 发现：`RESTARTS=2`，日志每次停在 `pip install`。
- 定位：startupProbe 总预算 150s 小于清华源最慢安装时间。
- 修复：`failureThreshold` 30→60（300s），新 Pod 0 重启；根治要预构建镜像。
- 经验：探针预算按"最慢可能值"定，而不是"通常值"。

### 2. 后续还会遇到吗？可以预防吗？

| 类型 | 预防 | 性质 |
|---|---|---|
| 环境依赖类（网络、安装） | 预构建镜像、chart 离线缓存 + SHA256、快照回滚 | 可根治 |
| 集成细节类（钉钉渲染、LLM 漂移、probe 预算） | 每次修复写成可复跑的验证命令，加进验收清单；改 ConfigMap 必须 rollout restart | 可能再出现，出现时快速确认 |

配套动作：ai-summary 有 `/metrics` 自监控；修复同步登记到 QA；代码配置和 VM 快照双向回滚。

### 3. 有备用方案吗？需要准备备用方案吗？

按爆炸半径排序，逐个回答"什么时候切、谁来切、怎么验证切换成功"：

| 单点 | 主方案 | 备用 | 状态 |
|---|---|---|---|
| 通知 | 钉钉加签 | `continue` 双路到 alert-webhook；邮件 webhook 已预留未启用 | 双路已做，邮件未启用 |
| LLM | DeepSeek | 规则降级模板；OpenAI 兼容接口可换 provider | 已实现 |
| 安装/网络 | GitHub / Docker Hub | chart 离线缓存 + SHA256 + 镜像加速 | 已做 |
| 数据源 | Loki / Tempo 单副本 | 无 | 实验取舍，记为已知偏差 |

原则：备用方案不只是"技术上有"，必须定义切换条件和执行者。实验里切换员是人，生产要自动化 + runbook。

### 4. 对接手生产工作有什么帮助？

四个帮助：

1. 会读别人的 values/manifests 并能说出字段影响面；
2. 排障按 SLO → 三类证据交叉核对的固定顺序，结论可复现；
3. 变更有纪律：先基线再动手，验收清单 + 快照；
4. 清楚 AI 的权力边界：模型只归纳，校验和降级在服务端。

诚实边界：没有真实 on-call、容量规划、多团队协作经验；故障合成、流量自造。项目把"能直接接手什么"和"需要带入什么"划清了。

### 5. 为什么要做这个项目？

两个动因：

1. 补"为什么每一跳存在"这一课——验收标准是能画出数据从产生到被 AI 使用的完整路径并解释每一跳；
2. 验证 AI 在运维场景的约束怎么落地：结论挂证据、数字用手工查询复现、模型失效有兜底。

坦白：这是个人实验，故障合成、流量自造，但问题来自真实场景（值班告警只说结果不说原因），方法用生产方法：基线、验收、快照、审计式记录。
