## Q&A

### 1. 为什么 inventory 用标准库，不用 FastAPI？

#### 问题

demo 和 ai-summary 都是 Python，为什么 inventory 不继续用 FastAPI？

#### 结论

inventory 只需要两个 GET：

```text
GET /healthz  -> ok
GET /item     -> {"item":"ok"}
```

用标准库 `http.server.ThreadingHTTPServer` 就够了，而且：

- 不需要 `pip install`，避开集群访问 PyPI 的问题；
- 启动快，镜像只用 `python:3.12-slim`；
- 依赖少，6b 的变量只有 `DELAY_MS` 和 `FAIL_MODE`。

用 `ThreadingHTTPServer` 而不是 `HTTPServer`，是为了一个 5 秒延迟请求不阻塞 readinessProbe。

#### 验证

```text
{"item":"ok"}
inventory served path=/item delay_ms=0 elapsed_ms=0.001
```

### 2. `/checkout` 的 trace 为什么要单独建 `inventory.call` 子 span？

#### 问题

已经有 `GET /checkout` 这个 server span，为什么还要子 span？

#### 结论

外层 span 只能说明“这个请求失败了”，不能说明时间花在哪里。子 span `inventory.call` 记录：

- `downstream.status`
- `downstream.duration_ms`

6b 注入 `DELAY_MS=5000` 后，Tempo 里能直接看到 `inventory.call` 超过 2000ms，AI 摘要才能把根因指向下游，而不是笼统写“请求失败”。

如果只靠日志，日志可能被采样或缺失；span 是独立证据源，能和指标、日志一起参与置信度计算。

#### 验证

正常请求返回 `ok`；后续 6b 会在 Tempo 查 `inventory.call` 时长。

### 3. 为什么 inventory 没启动时 `/checkout` 返回 504，而不是 500？

#### 问题

第一次验证时 inventory Deployment 还不存在，`/checkout` 返回了 504。

#### 结论

504 表示“网关/上游等待下游超时”，500 表示“服务自身处理失败”。这里失败发生在 demo 调下游的阶段，用 504 更贴近语义。

代码对所有下游异常统一返回 504：

```text
downstream timeout  -> 请求超过 2 秒
downstream error    -> 其他异常，如 DNS 解析失败、连接拒绝
```

日志里用 `downstream_error` 区分异常类型，卡片仍然能看到 `downstream` 关键字。

#### 验证

inventory 未创建时：

```text
wget: bad address 'inventory.demo.svc.cluster.local:8080'
/checkout -> 504 Gateway Timeout
demo_http_requests_total{path="/checkout",status="504"} 1.0
```

apply inventory 后：

```text
{"item":"ok"}
ok
demo_http_requests_total{path="/checkout",status="200"} 1.0
```

| 故障 | `/error` 立即 500 | `/checkout` 调下游超时 |
| 错误路径 | `/error` + `500` | `/checkout` + `504` |

标题相同是因为告警名相同；正文的路径、P95、T2、根因和建议不同，满足“可区分”要求。

### 发现的问题与修复

1. **BrokenPipeError**：loadgen 用 `wget -T 2`，demo 调 inventory 也超时 2 秒，客户端先断开，demo 写 504 时触发 `BrokenPipeError`。指标和 `downstream timeout` 日志在断开前已经写入，证据有效，但 traceback 淹没了日志。
   - 修复：`demo-loadgen.yaml` 改为 `wget -T 5`，让客户端能正常收到 504。
2. **钉钉重复显示反引号内容**：卡片渲染把 M5 路径和 T1 trace ID 放进反引号，钉钉 markdown 渲染后显示成两份：
   - `M5 错误路径：/checkout/checkout`
   - `T1 trace <id><id>`
   - 修复：`format_evidence_lines` 去掉反引号，M5 改成 `路径（状态码）` 格式。Pod 内渲染验证 `backticks: 0`，输出 `/checkout（504）`。
3. **startupProbe 150 秒不够**：`pip install` 从清华源安装时超过 150 秒，Pod 被 kubelet 重启 2 次。
   - 修复：`failureThreshold` 从 30 提到 60（300 秒）。新 Pod `RESTARTS=0`。
