### 2. 为什么 Loki 用 `Monolithic`，不是 `SingleBinary`？

#### 问题

Loki chart 的 values 里应该写 `deploymentMode: Monolithic` 还是 `SingleBinary`？

#### 结论

当前 `grafana-community/loki` chart `19.0.3` 使用 `Monolithic`。`SingleBinary` 是旧命名，继续照旧教程写会混淆。

单机学习环境用 `Monolithic` 就够了：

- 只有一个 Loki 实例。
- 使用文件系统存储。
- 不需要读写分离、分布式缓存和 MinIO。
- 资源占用小，适合 3 GB 内存的 worker。

安装时仍然通过 `singleBinary.replicas: 1` 控制实际副本。

### 3. 为什么把 Loki 放在 `k8s-worker-2`？

#### 问题

Loki 为什么固定到 `k8s-worker-2`，而不是随便调度？

#### 结论

因为 Loki 使用 `local-path` PVC，数据落在节点本地磁盘。如果 Pod 换节点，旧数据不会自动跟过去。

预检结果：

- worker-2 根分区：`/dev/sda3`，98G，已用 13G，可用 80G。
- worker-2 内存：total 2.9Gi，available 2.0Gi。
- Loki 计划 request `256Mi`，limit `1Gi`，空间和内存都够。
- server 上已经跑 Prometheus/Grafana，worker-2 只有系统组件，压力更小。

因此 values 里写了：

```yaml
singleBinary:
  nodeSelector:
    kubernetes.io/hostname: k8s-worker-2
```

### 4. `/var/lib/rancher/k3s/storage` 不存在，正常吗？

#### 问题

在 worker-2 上执行 `ls /var/lib/rancher/k3s` 只看到 `agent` 和 `data`，没有 `storage`，是不是 local-path 坏了？

#### 结论

正常。`local-path` provisioner 会在第一次有 PVC 需要绑定到该节点时创建存储目录。现在还没有 Loki PVC，所以目录不存在。

预检时用的是：

```bash
df -h /var/lib/rancher/k3s/storage
df -h /var/lib/rancher/k3s
```

第二条能看到目录所在分区，worker-2 根分区还有 80G，足够 5Gi PVC。不要手工 `mkdir` 一个空目录来“修复”，先让 local-path 自己创建。

### 5. 为什么 Fluent Bit 镜像要从 `cr.fluentbit.io` 换成 Docker Hub？

#### 问题

Fluent Bit chart 默认镜像是 `cr.fluentbit.io/fluent/fluent-bit`，为什么不直接用？

#### 结论

当前 k3s 的 registry mirror 只覆盖 `docker.io` 和 `registry.k8s.io`，没有覆盖 `cr.fluentbit.io`。在实验网络里直接拉取可能超时。

所以 values 里改成：

```yaml
image:
  repository: fluent/fluent-bit
  tag: "5.1.3"
```

这样会走 Docker Hub 和已有的 mirror。若 Docker Hub 上的 tag 不可用，再回退到 `cr.fluentbit.io`，并在验收文档里记录实际使用的镜像。

### 6. `helm lint grafana-community/loki` 为什么报 `Chart.yaml` 不存在？

#### 问题

执行：

```bash
helm lint grafana-community/loki -f /root/logging/values-loki.yaml
```

报错：

```text
Error unable to check Chart.yaml file in chart: stat grafana-community/loki/Chart.yaml: no such file or directory
Error: 1 chart(s) linted, 1 chart(s) failed
```

#### 根因

不是 values 写错，也不是 chart 不存在。

`helm lint` 的第一个参数必须是**本地 chart 目录**。`grafana-community/loki` 是 Helm 仓库里的 chart 引用，不是文件系统路径；`helm lint` 不会像 `helm install` 那样去仓库解析它，而是直接把它当成目录，所以找不到 `Chart.yaml`。

#### 修复

先把 chart 拉到本地，再 lint：

```bash
mkdir -p /tmp/helm-charts
helm pull grafana-community/loki --version 19.0.3 --untar -d /tmp/helm-charts
helm pull fluent/fluent-bit --version 0.58.3 --untar -d /tmp/helm-charts

helm lint /tmp/helm-charts/loki -f /root/logging/values-loki.yaml
helm lint /tmp/helm-charts/fluent-bit -f /root/logging/values-fluent-bit.yaml
```

预期：

```text
1 chart(s) linted, 0 chart(s) failed
```

#### 备选

如果只想验证模板能不能渲染，可以直接 `helm template`：

```bash
helm template loki grafana-community/loki \
  --namespace logging \
  --version 19.0.3 \
  -f /root/logging/values-loki.yaml > /tmp/loki-rendered.yaml
```

但 `lint` 更严格，建议至少做一次本地 chart 的 lint。

### 7. 为什么 `k8s-server` 没有 taint，还要写 toleration？

#### 问题

预检显示三个节点都没有 taint，Fluent Bit values 里为什么还写 control-plane toleration？

#### 结论

当前确实不需要，但写上无害，而且能防止以后给 server 加 taint 后 Fluent Bit 少一个节点。

toleration 只是“允许调度”，不是“强制调度”。没有对应 taint 时，它不会产生副作用。

### 8. 为什么每个 YAML 都要讲透？

#### 问题

YAML 能 `apply` 成功不代表真的理解；如果只照着抄，后面改字段或排错时会不知道从哪里下手。能不能每个 YAML 都先解释作用再执行？

#### 结论

可以，而且从今天开始按这个规则执行：

- 先说明文件类型：是 Helm values，还是 Kubernetes manifest。
- 再说明每个字段的作用：对象、开关、副本、资源、存储、网络、标签。
- 说明数据流：这个配置在日志链路的哪一段，前后是谁。
- 说明不写或写错的后果：是模板错误、调度失败，还是运行时空闲/报错。
- 最后才给执行命令和验证命令。

阶段 3 的四个文件已经整理成专题文档：

```text

```

后面新增或修改 YAML 时，先追加解释，再执行。
